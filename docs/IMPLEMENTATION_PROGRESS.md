## API integration follow-up (2026-10-22)

- Root cause: the ignored local `web/frontend/.env` config pointed `VITE_API_URL` at the hosted Render origin. Vite already had a working `/api` proxy to the local FastAPI server, but the frontend constructed absolute hosted URLs and bypassed that proxy. The current checkout registers the communication and performance routes used by the UI. The screenshot's 404 cannot identify which broadcast-mode request failed because the page catches the configuration update and broadcast errors together; the hosted service may also be missing the current route implementation.
- Changed development API-base resolution to always use `/api`; production URL normalization now avoids duplicate `/api` prefixes. Added better request error context, `.env.example`, and local setup troubleshooting to the README. The user's ignored `.env` remains local and unchanged.
- Performance uses the existing `GET /api/performance` saved-result route and `POST /api/performance/run?iterations=...` real benchmark route, backed by `run_performance_experiment`; no benchmark values are fabricated. CORS permits configured local origins and the hosted origin. Local Vite proxy requests are same-origin from the browser.
- Added frontend base-URL tests and backend route contract plus real benchmark API-function round-trip coverage.
- Verification: `./.venv/bin/pytest -q` passed (48 tests); frontend `npm test` passed; `npm run build` passed with the existing large-chunk warning; `npm run lint` exited 0 with the existing two React effect warnings; `git diff --check` passed. Direct local HTTP/browser smoke testing remains unavailable because this sandbox disallows local socket operations.
